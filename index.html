Параллельная работа света и звука

Учимся управлять несколькими исполнительными устройствами в одной программе. Светодиоды и пищалка работают согласованно, кнопка включает режим «Охрана», а перед включением даётся 5 секунд, чтобы выйти из комнаты.

Цель урока: научиться связывать несколько исполнительных устройств в одном коде.

Что понадобится

  • 1×Arduino Uno и USB-кабель
  • 1×Макетная плата
  • 3×Светодиоды: красный, синий, жёлтый
  • 3×Резисторы 220 Ом
  • 1×Пищалка (пассивный зуммер)
  • 1×Тактовая кнопка
  • 11×Провода «папа–папа»

Чему научимся

  • управлять звуком: tone(), noTone()
  • включать свет и звук синхронно
  • заменять delay() на millis()
  • подключать кнопку с INPUT_PULLUP
  • описывать работу устройства режимами

Теория

01

Исполнительные устройства

Arduino умеет не только «чувствовать» (кнопки, датчики), но и «действовать». Детали, которые что-то делают — светят, звучат, двигаются, — называют исполнительными устройствами. Сегодня их два: светодиод и пищалка.

Оба подключаются к цифровым пинам и управляются одинаково: пин делаем выходом (OUTPUT), а потом подаём на него 5 вольт (HIGH) или 0 вольт (LOW).

pinMode(7, OUTPUT);      // пин 7 — выход
digitalWrite(7, HIGH);   // подать 5 В — светодиод горит
digitalWrite(7, LOW);    // подать 0 В — светодиод погас
Главная идея урока

Arduino выполняет команды по одной, сверху вниз, но очень быстро — около 16 миллионов простых действий в секунду. Если команды для света и звука стоят рядом, для нас они срабатывают одновременно.

02

Светодиод: три правила подключения

  1. Полярность. Длинная ножка — анод (+), к ней приходит сигнал от пина. Короткая — катод (−), она идёт к земле GND. Со стороны катода на ободке корпуса есть срез.
  2. Резистор обязателен и стоит со стороны плюса: пин → резистор 220 Ом → длинная ножка. Без резистора потечёт слишком большой ток, и сгорит светодиод или пин Arduino.
  3. Короткая ножка — в минус через провод. Короткую ножку вставляем в свой столбец, а от него чёрный провод идёт в синюю шину «−». Шина соединена проводом с GND Arduino.

Почему именно 220 Ом? Посчитаем ток по закону Ома. На светодиоде «теряется» около 2 В, на резистор остаётся 5 − 2 = 3 В:

I = U / R = 3 В / 220 Ом ≈ 0,014 А = 14 мА

Пин Arduino спокойно выдаёт до 20 мА, светодиоду тоже нормально — светит ярко и не перегревается. Если резистор поставить со стороны минуса, ток будет тот же: в цепи из последовательно соединённых деталей он одинаковый везде. Мы ставим его со стороны плюса.

03

Пищалка: откуда берётся звук

Внутри пищалки — тонкая пластинка из пьезокерамики. Когда на неё подают напряжение, она чуть-чуть выгибается. Если очень быстро включать и выключать напряжение, пластинка дрожит и толкает воздух — получается звук.

Сколько раз в секунду пластинка дрожит, такая у звука частота. Её измеряют в герцах: 1000 Гц — это 1000 колебаний в секунду. Чем выше частота, тем выше и тоньше звук. Человек слышит примерно от 20 до 20 000 Гц, а пищалка громче всего звучит около 2000–4000 Гц.

Для сирены нужна пассивная пищалка: только у неё можно менять частоту. У пищалки тоже есть полярность: вывод «+» подключаем к пину, второй — к GND.

04

Команды tone() и noTone()

tone(8, 1000);        // пищать на пине 8 частотой 1000 Гц,
                      // пока не выключим
tone(8, 1000, 200);   // пищать 200 мс — звук выключится сам
noTone(8);            // выключить звук на пине 8
  • tone() не останавливает программу. Звук идёт «в фоне», а следующие команды выполняются сразу. Поэтому, чтобы дослушать звук, после tone() часто ставят delay().
  • Звук продолжается, пока его не выключат noTone() или не поменяют следующим tone() с другой частотой.
  • Одновременно может звучать только один tone().
Полезно знать

Пока работает tone(), на пинах 3 и 11 не работает плавная яркость analogWrite(): у них общий внутренний таймер. Сегодня мы используем только digitalWrite(), поэтому нам это не мешает.

05

Сирена: свет и звук по фазам

Сирена — это повторяющиеся фазы. В каждой фазе одновременно включаются свой цвет и свой звук. Секрет синхронизации простой: команды для света и для звука стоят рядом, без delay() между ними, а пауза — одна на всю фазу.

// Фаза 1: красный + высокий тон
digitalWrite(RED_LED, HIGH);
digitalWrite(BLUE_LED, LOW);
tone(BUZZER, 1000);
delay(400);
// Фаза 2: синий + низкий тон
digitalWrite(RED_LED, LOW);
digitalWrite(BLUE_LED, HIGH);
tone(BUZZER, 750);
delay(400);

Бывает и сирена-«вой»: частота плавно растёт и падает. Её делают циклом for, который много раз немного меняет частоту:

for (int freq = 600; freq <= 1500; freq = freq + 10) {
  tone(BUZZER, freq);   // каждый шаг — чуть выше
  delay(5);
}
06

Почему delay() мешает

delay(400) — это «сон»: 400 мс Arduino ничего не делает и ничего не замечает. Пока работает только сирена, это не страшно. Но если добавить кнопку, Arduino будет проверять её только между «снами», и короткое нажатие потеряется.

Представьте охранника, который каждые полсекунды закрывает глаза на 0,4 секунды. Вора он заметит не всегда.

Попробуйте в примере справа: нажимайте кнопку в разные моменты. Сверху Arduino «спит» в delay(), снизу проверяет кнопку постоянно.

07

millis() — часы внутри Arduino

millis() сообщает, сколько миллисекунд прошло с момента включения Arduino. Это секундомер, который никогда не останавливается. Вместо того чтобы «спать», программа постоянно смотрит на часы и спрашивает: «Не пора ли?»

unsigned long lastSwitch = 0;   // когда последний раз переключали

void loop() {
  if (millis() - lastSwitch >= 400) {   // прошло 400 мс?
    lastSwitch = millis();              // запомнили время
    // ... переключаем фазу сирены
  }
  // здесь же успеваем проверять кнопку
}

Так loop() выполняется тысячи раз в секунду, и в каждом проходе Arduino успевает и проверить кнопку, и, если пора, переключить сирену. Получается параллельная работа.

Аналогия

Когда варим яйца 10 минут, мы не стоим у плиты, глядя на кастрюлю. Мы запоминаем время, делаем бутерброды и иногда поглядываем на часы.

Тип unsigned long

Миллисекунд быстро становится много: через минуту — 60 000. В int помещается только до 32 767, поэтому время храним в unsigned long (до 4 миллиардов — это почти 50 дней).

08

Кнопка и INPUT_PULLUP

Кнопка — устройство ввода. Arduino читает её командой digitalRead(), которая возвращает HIGH или LOW.

Если пин ни к чему не подключён, он «висит в воздухе» и ловит помехи: digitalRead() выдаёт то HIGH, то LOW случайно. Чтобы этого не было, пин через резистор «подтягивают» к +5 В. У Arduino такой резистор есть внутри — его включает одна команда:

pinMode(BUTTON, INPUT_PULLUP);   // вход с подтяжкой к +5 В
int b = digitalRead(BUTTON);     // отпущена → HIGH, нажата → LOW

Кнопка подключается одной ножкой к пину 2, другой — к GND. Нажали — пин соединился с землёй, и Arduino прочитала LOW. Да, наоборот: нажата = LOW.

09

Дребезг контактов и кнопка-выключатель

Металлические контакты кнопки при нажатии несколько раз «подпрыгивают», и за 1–5 мс сигнал успевает много раз смениться. Arduino очень быстрая и может посчитать одно нажатие за несколько. Это называется дребезг.

Лечится просто: заметили изменение — подождали 50 мс, пока контакты успокоятся. А чтобы кнопка работала как выключатель (нажал — вкл, нажал ещё раз — выкл), ловим момент нажатия и переворачиваем переменную знаком ! («не»):

int button = digitalRead(BUTTON);
if (button != lastButton) {    // состояние изменилось
  delay(50);                   // ждём конца дребезга
  if (button == LOW) {         // это было нажатие
    guardOn = !guardOn;        // true ↔ false
  }
  lastButton = button;         // запоминаем
}
10

Режимы работы (состояния)

Сложное устройство удобно описывать режимами. Наша сигнализация всегда находится ровно в одном из трёх режимов и в каждом ведёт себя по-своему. Из режима в режим её переводят события: нажатие кнопки или истечение времени.

const int MODE_OFF    = 0;   // выключено
const int MODE_ARMING = 1;   // постановка: 5 секунд на выход
const int MODE_GUARD  = 2;   // охрана: сирена
int mode = MODE_OFF;         // текущий режим

if (mode == MODE_ARMING) {
  // мигаем жёлтым и смотрим, не прошло ли 5 секунд
}

Так устроены светофоры, стиральные машины, лифты и настоящие сигнализации. В программировании такую схему называют конечным автоматом.

Сборка по шагам

Резистор ставим со стороны плюса: он лежит вдоль ряда I и соединяет столбец провода от пина со столбцом длинной ножки (+). От столбца короткой ножки (−) чёрный провод идёт в синюю шину «−» — так же, как у пищалки.

Как работает код

  1. В начале даём пинам имена: RED_LED = 7 и так далее. Если провод придётся переставить на другой пин, достаточно поменять одно число.
  2. В setup() все три пина становятся выходами. Затем tone() → delay(200) → noTone(): писк длиной 0,2 секунды. Он звучит один раз — setup() выполняется только при включении.
  3. loop() повторяется бесконечно: фаза 1 (горит красный) и фаза 2 (горит синий) по 300 мс.
  4. Следите за подсветкой строк в коде: она показывает, какая строка выполняется прямо сейчас. Почти всё время программа стоит на строках с delay().

Если не работает

  • Светодиод не горит. Длинная ножка (+) — в одном столбце с концом резистора, короткая (−) — в столбце, откуда чёрный провод идёт в шину «−». Перевёрнутый светодиод не горит: поменяйте ножки местами.
  • Не горит ничего. Провод GND от Arduino должен идти в ту же синюю шину «−», куда приходят чёрные провода от светодиодов.
  • Пищалка молчит. Её ножки должны стоять в разных столбцах. «+» — к пину 8, «−» — к GND.
  • Звук хриплый или один и тот же. Скорее всего, пищалка активная. Для сирены нужна пассивная.

Попробуй изменить

  • Поставь BLINK_TIME = 80 — получится стробоскоп.
  • Добавь в каждую фазу короткий щелчок: tone(BUZZER, 2000, 20);
  • Сделай «двойную вспышку»: красный мигает два раза быстро, потом синий два раза.

Код в окне можно редактировать и сразу запускать в симуляторе кнопкой «Запустить изменённый код».

Сборка

Схема та же, что в задании 1, — ничего добавлять не нужно. Загрузите новый скетч.

Как работает код

  1. tone() не ждёт: звук начинается и продолжается сам, пока следующий tone() не поменяет частоту. Поэтому в каждой фазе свой тон звучит ровно 400 мс.
  2. Команды света и звука стоят подряд, без паузы, а delay() — одна на фазу. Значит, свет и звук меняются в один и тот же момент.
  3. Посмотрите на график под симулятором: края красной и синей полос совпадают со сменой частоты пищалки.
  4. В варианте «Вой» цикл for меняет частоту от 600 до 1500 Гц шагами по 10 Гц каждые 5 мс: 91 шаг ≈ 0,45 с. Пока звук растёт, горит красный, пока падает — синий.

Если не работает

  • Звук не меняется. Проверьте, что в фазах стоят разные константы: HIGH_TONE и LOW_TONE.
  • Свет и звук «разъехались». Между командами фазы не должно быть delay() — только одна пауза в конце фазы.
  • Вой звучит ступеньками. Это нормально: частота меняется шагами по 10 Гц. Уменьшите STEP до 5 — станет плавнее.

Попробуй изменить

  • Поменяй тоны: HIGH_TONE = 1500, LOW_TONE = 500.
  • Сделай фазы по 150 мс — сирена станет тревожнее.
  • В варианте «Вой» поставь STEP_TIME = 10 — вой станет медленнее.

Сборка по шагам

Кнопку ставим поперёк центральной канавки, чтобы её ножки оказались в разных половинах платы. Провод от D2 и провод на GND — в столбцы по разные стороны кнопки.

Как работает код

  1. loop() теперь выполняется тысячи раз в секунду. В каждом проходе две быстрые проверки: кнопка и сирена.
  2. Кнопка. Если состояние изменилось, ждём 50 мс (дребезг) и, если это нажатие, переключаем guardOn. При выключении сразу гасим свет и звук.
  3. Сирена. Условие guardOn && now - lastSwitch >= PHASE_TIME читается так: «охрана включена и с последней смены фазы прошло 400 мс». Тогда меняем фазу и сразу включаем нужный цвет и тон.
  4. Монитор порта показывает сообщения «Охрана ВКЛЮЧЕНА» и «Охрана выключена» — так удобно проверять программу.
  5. Нажмите вариант «Ошибка: delay()» и попробуйте быстро нажимать кнопку, пока звучит сирена: нажатия теряются. В подсветке кода видно, что программа почти всё время стоит на delay().

Если не работает

  • Сирена включается сама или «дёргается». Кнопка стоит не поперёк канавки или провода попали в один столбец с одной стороны кнопки.
  • Кнопка не реагирует. Проверьте pinMode(BUTTON, INPUT_PULLUP) и провод от второй ножки кнопки к GND.
  • Одно нажатие срабатывает дважды. Увеличьте паузу дребезга до 80–100 мс.
  • В Мониторе порта ничего нет. Откройте его после загрузки и выберите скорость 9600.

Попробуй изменить

  • Замени INPUT_PULLUP на INPUT и запусти в симуляторе: вход начнёт «шуметь», сирена будет включаться сама.
  • Удали строку delay(50); и проверь на настоящей кнопке, всегда ли нажатие срабатывает один раз.
  • Сделай сирену «вой» на millis(): каждые 5 мс меняй частоту на 10 Гц.

Сборка по шагам

Как работает код

  1. Вместо bool guardOn теперь int mode: режимов три, а не два. Номера режимов — константы MODE_OFF, MODE_ARMING, MODE_GUARD.
  2. Кнопка: из режима ВЫКЛ переводит в ПОСТАНОВКУ и засекает время armStart = now. Из любого другого режима — выключает всё.
  3. Постановка: каждые 250 мс жёлтый светодиод меняет состояние. При вспышке звучит «тик» tone(BUZZER, 2000, 30) — он выключится сам через 30 мс. Когда now - armStart >= 5000, режим меняется на ОХРАНУ.
  4. Охрана: работает та же сирена, что в задании 3.
  5. Над графиком симулятора видно текущий режим и сколько секунд осталось до включения охраны.

Если не работает

  • Жёлтый не мигает. Проверьте провод от D5, резистор вдоль ряда I и чёрный провод от короткой ножки в шину «−».
  • Сирена включается сразу. Убедитесь, что armStart = now; стоит внутри ветки, где режим становится MODE_ARMING.
  • Сирена не выключается. В ветке выключения должны быть noTone(BUZZER) и гашение всех трёх светодиодов.

Попробуй изменить

  • Дай на выход 10 секунд вместо 5.
  • В последние 2 секунды мигай вдвое быстрее. Подсказка: if (now - armStart > 3000).
  • Добавь «датчик двери» — вторую кнопку. Тогда в режиме охраны сирена молчит и включается, только когда «открыли дверь».

1Почему свет и звук меняются «одновременно», хотя команды выполняются по очереди?

Между этими командами нет паузы, а Arduino выполняет их за миллионные доли секунды — для глаза и уха это один момент.

2Чем tone(8, 1000) отличается от tone(8, 1000, 200)?

Первая команда звучит, пока не вызовут noTone(8) или другой tone(). Вторая сама выключит звук через 200 мс.

3Почему в задании 3 нельзя оставить delay(400) в сирене?

Во время delay() Arduino не проверяет кнопку, и короткое нажатие теряется.

4Что вернёт digitalRead() для нажатой кнопки с INPUT_PULLUP?

LOW: нажатая кнопка соединяет пин с землёй. Отпущенная — HIGH благодаря подтягивающему резистору.

5Зачем нужна пауза 50 мс после изменения состояния кнопки?

Чтобы переждать дребезг контактов: иначе одно нажатие может посчитаться за несколько.

6Почему время храним в unsigned long, а не в int?

int вмещает максимум 32 767 — это всего 32 секунды в миллисекундах. unsigned long хватит почти на 50 дней.

7Сколько режимов у сигнализации в задании 4 и что переключает их?

Три: выключено, постановка, охрана. Переходы вызывают нажатие кнопки и истечение 5 секунд.

Теория

От поворота ручки до числа в программе — по шагам.

01

Цифровой и аналоговый сигнал

Цифровой сигнал похож на выключатель: у него только два значения — 0 В или 5 В (LOW или HIGH). Аналоговый похож на ручку громкости: он может быть любым в диапазоне — 1,7 В, 3,24 В и так далее.

Цифровые пины D0–D13 отвечают только «да» или «нет». Чтобы измерить «сколько», у Arduino Uno есть шесть аналоговых входов: A0–A5.

02

Потенциометр

Потенциометр — это резистор с тремя выводами и ручкой. Внутри — подковообразная дорожка из резистивного материала (у нас 10 кОм) и подвижный контакт — движок.

  • Крайние выводы подключены к концам дорожки: один — к 5V, другой — к GND.
  • Средний вывод соединён с движком. Его подключаем к аналоговому входу A0.
  • Крутим ручку — движок скользит по дорожке, и напряжение на среднем выводе плавно меняется от 0 до 5 В.

Покрутите ручку в примере справа мышкой или пальцем. Пример показывает сразу всё: где движок, какое напряжение, какое число получит Arduino и как это число записано в двоичном виде.

03

Делитель напряжения

Два резистора, соединённые последовательно между 5 В и землёй, делят напряжение. В точке между ними получается часть от 5 В — тем больше, чем больше нижний резистор:

Uвых = 5 В × R2 / (R1 + R2)
  • R1 = R2 = 5 кОм → U = 5 × 5 / 10 = 2,5 В (половина).
  • R1 = 7,5 кОм, R2 = 2,5 кОм → U = 5 × 2,5 / 10 = 1,25 В (четверть).

Потенциометр — это делитель, у которого соотношение R1 и R2 меняется поворотом ручки. Их сумма всегда равна 10 кОм.

04

АЦП: как напряжение превращается в число

Внутри Arduino есть АЦП — аналого-цифровой преобразователь. Он делит диапазон 0–5 В на 1024 ступеньки и сообщает номер ступеньки: от 0 до 1023.

Почему 1024? Потому что АЦП 10-битный: из 10 двоичных разрядов можно составить 210 = 1024 разных числа.

1,25 В≈ 256на четверть

Шаг АЦП

Одна ступенька — примерно 0,005 В (5 мВ). Число может немного «дрожать» на ±1–2: это обычный электрический шум, так и должно быть.

Не путайте

Аналоговый вход A0 и цифровой пин D0 — разные пины. analogRead(A0) читает именно аналоговый вход, pinMode для него писать не нужно.

05

analogRead() и Монитор порта

int value = analogRead(A0);   // число от 0 до 1023

Монитор порта — окно, в которое Arduino по USB-кабелю пишет сообщения. Это главный способ узнать, что происходит внутри программы.

void setup() {
  Serial.begin(9600);       // включить связь, скорость 9600 бод
}
void loop() {
  int value = analogRead(A0);
  Serial.print("A0 = ");    // print — без перехода на новую строку
  Serial.println(value);    // println — с переходом
  delay(200);
}
  • Открыть: значок лупы справа вверху Arduino IDE или Ctrl + Shift + M.
  • Скорость в окне монитора должна совпадать с Serial.begin() — 9600. Иначе вместо чисел будут непонятные символы.
  • Если печатать только числа (Serial.println(value)), «Плоттер по последовательному соединению» нарисует график.
06

map(): пересчёт из одного диапазона в другой

Число 0…1023 часто нужно превратить во что-то другое: в паузу 50…1000 мс, в угол 0…180°, в количество светодиодов. Для этого есть функция map():

int pause = map(value, 0, 1023, 50, 1000);
//              что    из диапазона  в диапазон
  • map(0, 0, 1023, 50, 1000) → 50
  • map(512, 0, 1023, 50, 1000) → 525
  • map(1023, 0, 1023, 50, 1000) → 1000

map() работает с целыми числами и отбрасывает дробную часть. Диапазон можно и перевернуть: map(value, 0, 1023, 1000, 50) — тогда чем дальше ручка, тем меньше результат.

07

Пороги: шкала и авария

Чтобы светодиоды загорались по очереди, каждому назначаем порог: светодиод горит, если значение больше его порога.

if (value > 200) {
  digitalWrite(LED1, HIGH);   // выше порога — горит
} else {
  digitalWrite(LED1, LOW);    // ниже — не горит
}

Авария — это ещё один порог, близкий к максимуму: if (value > 1000). Ставить ровно 1023 не стоит: из-за шума значение может не дотягивать до максимума.

Для любознательных: гистерезис

Если ручка стоит ровно на пороге, шум заставит сигнал включаться и выключаться. Решение — два порога: включать аварию при значении больше 1000, а выключать только при меньше 980.

Сборка по шагам

Ножки потенциометра — в ряд F, ручкой к центру платы. Левый вывод — земля, средний — сигнал, правый — 5V.

Как работает код

  1. analogRead(POT) возвращает целое число от 0 до 1023. Константа POT = A0 — это номер аналогового входа.
  2. value * 5.0 / 1023.0 переводит число в вольты. Пишем 5.0, а не 5, чтобы вычисления шли с дробной частью: тип float.
  3. Несколько Serial.print() собирают одну строку, последний Serial.println() переводит курсор на новую.
  4. delay(200) — измеряем 5 раз в секунду, чтобы числа не мелькали слишком быстро.

Если не работает

  • В мониторе непонятные символы. Выберите в окне скорость 9600.
  • Значение всегда около 0 или около 1023. Средний вывод не на A0, или на потенциометр не приходит 5V либо GND.
  • Числа скачут хаотично от 0 до 1023. Провод от среднего вывода не вставлен — вход «висит в воздухе».
  • Крутим по часовой, а число уменьшается. Поменяйте местами провода 5V и GND.

Попробуй изменить

  • Оставь только Serial.println(value); и открой «Плоттер по последовательному соединению».
  • Поставь delay(20) — значения будут обновляться почти мгновенно.
  • Выведи значение в процентах: map(value, 0, 1023, 0, 100).

Сборка по шагам

Резистор ставим со стороны плюса: вдоль ряда I, между столбцом провода от D7 и столбцом длинной ножки (+). От столбца короткой ножки (−) чёрный провод идёт в синюю шину «−».

Как работает код

  1. В начале каждого loop() читаем ручку и сразу считаем паузу: map(value, 0, 1023, 50, 1000).
  2. Светодиод горит pause мс и столько же не горит. Чем больше пауза, тем медленнее мигание.
  3. Обратите внимание: ручку Arduino «видит» только один раз за цикл мигания. При паузе 1000 мс реакция может запаздывать до 2 секунд. Это снова «сон» в delay(), как на уроке 8.
  4. Вариант «Пауза = значение»: delay(value) — пауза прямо пропорциональна повороту. Около нуля светодиод мигает так быстро, что кажется, будто он просто горит.

Если не работает

  • Светодиод не горит. Длинная ножка (+) — в столбец конца резистора, от столбца короткой (−) — чёрный провод в шину «−». Перевёрнутый светодиод не горит.
  • Мигает всегда одинаково. Проверьте, что в delay() стоит переменная pause, а не число.
  • Реагирует с опозданием. Так и должно быть при длинной паузе — см. пункт 3 слева.

Попробуй изменить

  • Переверни диапазон: map(value, 0, 1023, 1000, 50).
  • Сделай мигание без delay() с помощью millis() — реакция на ручку станет мгновенной.

Сборка по шагам

Светодиоды стоят в ряд слева направо: LED1 → LED4. У каждого свой резистор со стороны плюса и свой чёрный провод от короткой ножки в шину «−». Провода идут от D7, D6, D5, D4 — так они не перекрещиваются.

Как работает код

  1. Четыре одинаковых блока if … else: каждый светодиод сравнивает значение со своим порогом — 200, 400, 600 или 800.
  2. Пороги идут по возрастанию, поэтому светодиоды загораются строго по очереди.
  3. Serial.println(value) печатает только число — откройте Плоттер, увидите график.
  4. Вариант «Массив и цикл»: пины лежат в массиве LEDS[4], а map(value, 0, 1023, 0, 5) сразу даёт уровень 0…5. Цикл for зажигает светодиоды с номерами меньше уровня.

Если не работает

  • Один светодиод не горит никогда. Проверьте его полярность и провод.
  • Загораются не по порядку. Перепутаны провода: LED1 → D7, LED2 → D6, LED3 → D5, LED4 → D4.
  • Последний светодиод не загорается. Ручка не доходит до 800 — проверьте 5V на потенциометре.

Попробуй изменить

  • Сделай шкалу «наоборот»: при повороте светодиоды гаснут.
  • Сделай режим «точка»: горит только один светодиод, соответствующий уровню.

Как работает код

Вопросы для закрепления, задания для быстрых и план урока для учителя.

1Сколько разных значений может вернуть analogRead() и почему?

1024 значения, от 0 до 1023: АЦП Arduino Uno 10-битный, 210 = 1024.

2Какое число получим, если на A0 ровно 2,5 В?

Около 512 — середина шкалы.

3Каким будет напряжение в средней точке делителя, если R1 = R2?

Половина питания: 2,5 В.

29: 300 × 100 / 1023 = 29,3, дробная часть отбрасывается.

Все скетчи проверены компиляцией для Arduino Uno. Код из окна можно скопировать кнопкой «Копировать» и вставить в Arduino IDE. Симулятор на странице выполняет тот же код, что показан в окне.

Как не ошибиться, когда переписываете код
  • Серый текст после // и между /* и */ — комментарии. Их можно не переписывать: Arduino их не читает. Кнопка «Без комментариев» оставит только код.
  • В конце каждой команды стоит точка с запятой ;
  • Скобки всегда парами: ( ) и { }. Каждую открытую фигурную скобку нужно закрыть.
  • Большие и маленькие буквы различаются: digitalWrite, HIGH, OUTPUT — ровно так.
  • = — записать значение, == — сравнить. В if почти всегда нужно ==.
  • Цифра 0 и буква O — разные символы. Имена пишем латиницей, русский текст — только внутри кавычек " ".
  • Переписали — нажмите «Проверить» (галочка) в Arduino IDE. Если есть ошибка, IDE подсветит строку с ней.
